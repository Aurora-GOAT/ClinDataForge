# PHI第二阶段预注册评测协议（v2）

协议版本 v2，日期 2026-10-25。正式测试前冻结数据、方法配置及源码指纹。旧60条压力集仅为历史诊断，绝不参与本协议的选择或测试。
v2 相对 v1 的变化：方法由三路扩展为四路（新增 Presidio 作为 B，原 GLiNER 顺延为 C，融合为 D）；标签由五类扩展为八类；补充开发集选择规则与量化权重排除记录。

## 数据与独立性

英文来自独立公开合成医疗查询源 **ASQ-PHI v1**（MIT，1,051 条，2,973 个 PHI 元素）；中文由本仓库独立构建任务编写（40 个模板族 × 8 条）。两者都不调用现有规则、旧生成器或模型来挑选"能识别"的样本。实际来源、许可、版本、标签产生方式、筛选和变换详见 `PHI_DATA_CARD_CN.md`。所有原始来源、变换源码和划分产物记录 SHA256，并由 `scripts/audit_phi_dataset.py` 用**另一套掩码与相似度定义**重新核验。

标签规范为 Unicode 码点、左闭右开精确跨度；八类：NAME、PHONE、PATIENT_ID、DATE、ADDRESS、SSN、EMAIL、INSURANCE_ID。原规则 MRN 映射为 PATIENT_ID。ADDRESS 包含地理/机构位置，不等同于狭义街道地址。ASQ-PHI 的 `UNIQUE_IDENTIFIER`、`ACCOUNT_NUMBER` 与 `MEDICAL_RECORD_NUMBER` 一并映射为 PATIENT_ID；`FAX_NUMBER` 映射为 PHONE；`CERTIFICATE_LICENSE_NUMBER` 与 `IP_ADDRESS`（合计 2 个元素）声明为范围外，不计入分母并在数据卡披露。保护医学内容的 CLINICAL 跨度为独立的程序标注层，不冒充医生审核。

按"近重复连通分量"划分 train/dev/test：任意两份文档只要满足以下任一条件即并入同一分量，分量不得跨划分——
1. PHI 与临床段遮蔽后的骨架完全相同；
2. 骨架 5-gram Jaccard ≥ 0.50；
3. 另一套掩码（保留数字、仅保留字母数字与汉字）6-gram Jaccard ≥ 0.50；
4. 同一中文模板族（作者声明）。

train 用于接口检查与预热，dev 用于阈值与融合组合选择，test 冻结后仅一次正式运行。方法开发任务禁止查看 test 正文、错误案例或调参。

## 方法

- **A**：保留既有 `operators.find_phi`，除 MRN→PATIENT_ID 的评测层映射外不增强。
- **B**：Microsoft Presidio AnalyzerEngine（2.2.364）+ 本地显式加载的 spaCy `en_core_web_lg`。仅预置识别器，不添加项目自定义的病历号规则。
- **C**：本地预训练 GLiNER（`urchade/gliner_multi_pii-v1`，ONNX fp16 转换）真实 CPU 推理，纯 numpy 前端，无 torch、无远程推理。
- **D**：C 与"任务专用上下文规则"的精确跨度并集；候选组合含是否并入 Presidio，在开发集决定。

模型不可运行必须失败并报告，不能用模拟结果、测试替身或空预测冒充。fp16 之外的 int8 动态量化权重经探针验证为表征坍缩（同一探针最大跨度概率仅 0.202，prompt 与词表征互相不可区分），已排除，记录于 `models/phase2_gliner_pii/README.md`。

## 开发集选择规则（预注册，v2.1）

只在 dev 上、只在下列网格中选择：C 的阈值 t ∈ {0.05, 0.10, …, 0.90}；B 的阈值 s ∈ {0.0, 0.1, …, 0.9}；D 的组合 ∈ {规则+GLiNER(t)} ∪ {规则+GLiNER(t)+Presidio(s)}。一次推理导出全部门槛候选后离线扫描，不重复推理。对 B、C、D **分别**独立选择。

选择规则（v2.1）：
1. 最大化实体级精确跨度 F1；
2. 若并列，取召回率更高者；
3. 若仍并列，取保护医学字符误删率更低者。

**v2.1 修订记录（必须在任何场合一并引用）**：v2 的规则是"先最大化召回，再在 1 个百分点内取 F1 最大"。在 dev 前沿上该规则选中了网格中最低的阈值，其代价是掩码掉 22.8% 的保护医学字符、并改动 100% 的无 PHI 硬负样本——即几乎放弃全部可用性。因此规则改为 F1 最大化。该修订发生在**读取任何 test 数据之前**，但确实是在观察到 dev 前沿之后作出的，属于开发集驱动的设计修正，不是测试集调参；dev 前沿全表与"召回优先"备选点在报告中一并给出，读者可自行判断取舍。

正式测试前以锁文件固定方法代码、模型、配置和数据 SHA256，不因测试结果修改方法。

## 指标定义

1. 实体级精确跨度 micro P/R/F1；标签和起止偏移须同时正确。错误边界或标签同时产生 FP 和 FN。无预测时 precision 为 null；无金标时 recall 为 null，不用人为 1.0 填补。
2. 八类独立指标，以及中文/英文、数据来源的分层指标。
3. 有 PHI 记录的"全部实体精确识别率"和"全部金标字符被掩码率"分别报告；另列全部记录指标及无 PHI 记录数与"无 PHI 记录被任意掩码率"。覆盖已有金标不代表没有未标 PHI。
4. 医学误删率＝掩码覆盖的 CLINICAL 字符数／全部保护医学字符数；另报医学跨度受损率、全部非 PHI 字符误删率。CLINICAL 标签不完整，不能宣称覆盖全部医学信息。
5. 每条输入保留原始预测跨度及充分统计，合成测试错误案例全部留档。掩码使用预测跨度的并集，重叠不能留下未处理的尾部。

## 配对不确定性与资源测量

在同一组文档上配对比较 B−A、C−A、D−A、B−D、C−D。按语言分层，对近重复连通分量进行有放回 cluster bootstrap，2000 次，固定 seed=20261025，报告差值及 95% 百分位区间。主要比较实体召回、F1、完整金标字符覆盖率和保护医学字符误删率。区间条件于该合成来源与固定方法，不代表真实患者分布，也不消除预训练污染风险。

每个方法在独立进程中测量；分开记录初始化时间、train 文档预热时间、推理总时长、单文档时延、吞吐和峰值进程 RSS。峰值内存含 Python、模型加载和推理；不是仅权重大小。CPU 线程配置记录；加载/冷启动不计入推理吞吐。小样本本机计时不外推生产吞吐。

## 安全集成与结论门槛

默认真实患者入口和正文出口继续关闭。只有经来源指纹匹配的合成演示输入可显式请求脱敏文本输出；普通 `--synthetic` 声明不能开启此出口。隔离行仍只保存元数据，模型不可用/指纹不符/推理失败应关闭出口并报告。基准覆盖八类、程序标注、有限语言和格式；即使金标残留为 0 也不能称为生产级或真实患者安全。

本阶段不进行 SFT、付费 API、外部 GPU、隐私上传或公开发布。
