# Codex开发计划：按验收门槛推进，而非盲目升级版本

## 2026-10-25 第一阶段审计状态

第一阶段代码/历史实验复核已完成，见 `PHASE1_AUDIT_CN.md`。这不等于以下P0独立验收通过：目前仅完成元数据输出收紧及评测/生成器/工程缺陷修复，未引入独立来源PHI测试集或模型对照。旧压力集完整覆盖记录仅10/60，禁止以工程回归测试数量证明脱敏安全。

## P0 — 把脱敏从“模板演示”做成可靠研究问题（优先）

**问题：** 现有730条模板合成数据的PHI recall为100%，但60条新格式压力集中仅55.6%。规则对未见格式脆弱，存在泄露风险。**当前禁止真实患者原始文本输入**。

1. 加入独立来源的开放许可、无真实隐私风险的PHI标注数据（如合法公开合成/去标识化挑战数据），建立train/dev/test按人和模板分组。
2. 在合规许可允许下使用医学NER/通用文本分类器，比较纯规则、NER、规则+NER。不得通过持续看test集调参数。
3. 做误杀/漏检代价评估、PHI标签边界（姓名、联系方式、病历号、日期等）、数字相似实体误检、对抗/格式变化。
4. 在输入来源、证据完整性或PHI风险不明时**不给出原始正文**；任何“疑似风险”进只含元数据的隔离区，并提供人工审核入口。
5. 复现前后精确跨度F1、记录级“零残留”率、拒绝率、耗时和问题样例。不可把模板内100%写作外部准确率。

**验收：** 新第三方或独立生成来源的真正冻结测试集、原始金标、完整脚本、误差清单、明确仍失败的场景。

## P1 — 病历、检验、处方多源处理与高价值数据筛选

1. 新增可追溯的FHIR样式资源/处方/独立检验记录接入（优先公开演示数据；不收集真实个人数据）。
2. 建立代码表：LOINC术语/单位、药品名称与用药剂量结构化；保留无法确认字段不自动映射。
3. 批量近重复、来源去重、就诊级一致性检查、数据漂移与噪声诊断。
4. 生成按来源和质量门槛分级的数据集，人工抽检：可用/待复核/拒绝；不能把自动生成的字段当人工真值。
5. SQL和Parquet导出、指标仪表盘，处理异常后可断点恢复。

**验收：** 有不同来源的真实可用格式、独立评价集、数据卡与对照实验。

## P2 — 只做与下游模型增益有关的数据闭环

1. 如果用户批准算力及许可，构建小规模人工复核的结构化抽取数据，用LoRA SFT而不是训练一个新基座。
2. 实验必须设立模型/提示词/种子/超参数/样本划分的冻结协议和未见测试集，比较原模型、不同数据质量子集训练前后提取F1。
3. 同时记录训练时间、成本、错误率、公平性和有效数据量，进行样本量/质量消融。
4. 没有真实GPU训练日志就不能将SFT、RLHF、模型准确率提升写成已完成。

## P3 — 工程部署与面试演示

API、可交互的质控标注小网页、Docker、CI、GitHub脱敏发行包、公开数据许可核验、5分钟Demo与技术面试讲稿。禁止自动上传隐私材料。

## 优先级原则

先产出**被真实独立指标支持的1个核心能力**，再扩功能。禁止仅将测试条数、合成文本量、版本号当作项目业绩。
