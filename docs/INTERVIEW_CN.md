# 第一阶段验收后的面试叙述

“我在做一个医疗大模型数据质量处理原型，重点研究文本解析、单位标准化、重复识别、隐私风险和质量评测。

初版在730条自行生成的合成记录上分数很高，但我重新审计后发现，规则在六类压力模板上的PHI召回率只有55.6%，只有10/60条记录覆盖全部标注实体。我因此关闭了流水线正文和SFT文本导出，只保留允许列表中的审计元数据。

审计还发现两个会改变结论的问题：六处检验误差来自生成器误改ALT，而非抽取器；历史公开数据汇总与现存源不一致。我保留旧记录，另建修正实验，增加数据划分验证、输出故障回滚、隐私canary和重复链接检查。下一步是在冻结的独立来源数据上比较规则和本地模型，而不是将模板分数写成真实患者效果。”

## 追问与可辩护边界

| 追问 | 可用回答 |
|---|---|
| 为什么测试全绿仍有问题？ | 原28项主要验证既定行为，缺少非预期输入、漏检正文出口、跨患者划分和生成器独立核验。新增测试来自已复现缺陷，不代表外部泛化。 |
| 检验F1为何变为1.0？ | 温度替换误匹配ALT，修正六条合成正文后与原金标一致；算法没有因此获得独立抽取能力提升。 |
| 如何证明隐私安全？ | 目前不能证明真实病历安全。只证明测试覆盖的持久化管线不写正文；元数据仍可关联，真实输入继续禁用。 |
| 同规则再扫描为何不够？ | 第一次漏识别的格式会被第二次同规则继续漏掉，残留检查不是独立证据。 |
| 去重为何限制就诊内？ | 不同就诊可具有相似描述；相同就诊也可能是检验值更新，因此先检查已抽取字段冲突。未抽取语义仍是局限。 |
| 历史MIMIC数字怎么说？ | 222/64/545缺少可定位源指纹，当前不能复现；现存源独立重算为85/40/21，只能讲可核验的后者。 |
| 是否训练过大模型？ | 没有。历史候选未经人工审核，当前候选文本暂停导出；没有SFT、LoRA或下游增益结果。 |
| 吞吐能扩展到多大？ | 只测量730条、单进程、本机、小内存输入；新旧输出策略和环境不同，不直接比较速度提升，不外推TB级。 |

不得声称真实脱敏100%、生产合规、医生标注训练集、独立手写全部代码或完成医疗多模态平台。项目由AI编程工具辅助开发，面试前应能亲自复现并解释核心代码。

所有数字以 `reports/phase1_20261025/` 和 `PHASE1_AUDIT_CN.md` 为准；初版文档保存在 `delivery-v0.1` 标签。
