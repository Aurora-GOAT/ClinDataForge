## 0. 结论摘要（先说结论）

在**冻结测试集**（632 条记录、1,942 个金标 PHI 实体，其中英文 456 条来自 ASQ-PHI，中文 176 条来自本仓库独立模板）上：

| 方法 | Recall | Precision | F1 | 金标字符残留率 | 保护医学字符误删率 | 无 PHI 记录被改动率 |
| --- | --- | --- | --- | --- | --- | --- |
| A 原规则 | 0.0803 | 0.7800 | 0.1457 | 0.9032 | 0.0000 | 0.0000 |
| B Presidio (spaCy lg) | 0.3084 | 0.3905 | 0.3446 | 0.5383 | 0.2120 | 0.7793 |
| C GLiNER (fp16 ONNX) | 0.8363 | 0.7522 | 0.7920 | 0.0704 | 0.1442 | 0.9655 |
| **D 融合（规则+GLiNER）** | **0.9042** | **0.7566** | **0.8238** | **0.0536** | 0.1442 | 0.9655 |

配对 cluster bootstrap（2,000 次，按语言分层，按近重复分量重采样）：

- **D − A：召回 +0.8239，95% 区间 [+0.8058, +0.8422]；F1 +0.6782 [+0.6557, +0.7012]**
- **D − C：召回 +0.0680 [+0.0541, +0.0822]；F1 +0.0318 [+0.0229, +0.0404]**
- D − B：召回 +0.5958 [+0.5741, +0.6175]；保护医学误删率 **−0.0678 [−0.0932, −0.0437]**（D 比 Presidio 少删医学内容）

> 偏差记录：协议 v2.1 文字写的是"比较 B−A、C−A、D−A、B−D、C−D"，实现输出的是同一对比较但方向相反（D−B、D−C，差值定义为后者 − 前者）。协议文件已随实验冻结并被锁文件哈希校验，因此不在本轮改动；下一轮冻结前会修正文字表述。

所有关键区间都不跨 0，因此"融合优于原规则"与"融合优于单模型"是**在该合成分布上可复现的结论**，不是抽样噪声。

**但这不是"真实患者病历安全"的结论**：数据 100% 合成、标签为机器标签、无医生复核；D 仍有 186 个金标实体完全未被识别，金标字符残留率 5.36%，并且 96.55% 的无 PHI 硬负样本仍被改动。**默认真实文本出口继续保持关闭。**

## 1. 方法定义

| 方法 | 实现 | 关键约束 |
| --- | --- | --- |
| A | `clinforge.operators.find_phi`（v0.1 原规则，除 MRN→PATIENT_ID 评测映射外未改） | 纯正则，仅识别带显式关键字的姓名/电话/病历号 |
| B | Microsoft Presidio AnalyzerEngine 2.2.364 + 本地显式加载 spaCy `en_core_web_lg` 3.8.0 | **仅预置识别器**，未添加项目自定义病历号规则；英文 NLP，中文无 NER |
| C | `urchade/gliner_multi_pii-v1` 的 ONNX fp16 转换，纯 numpy 前端，CPU | 无 torch、无远程推理；权重 SHA256 每次运行校验 |
| D | C 的跨度 ∪ 任务专用上下文规则（`clinforge.phi_rules`） | 阈值与融合组合均在 dev 上选定（见第 3 节） |

### 一个必须记录的负面结果：int8 量化权重不可用

仓库同时提供了 `onnx/model_quantized.onnx`（int8 动态量化）。在同一探针上，它的最大跨度概率只有 **0.202**，各 prompt 与词表征的余弦相似度全部落在 −0.06 ~ −0.03 的同一窄带内，即**表征坍缩**；换成 fp16 权重后同一探针立刻给出 `Anna Smith/NAME 1.00`、`April 12, 2023/DATE 0.996`、`Boston/ADDRESS 0.989`。因此本项目使用 fp16 权重，并在 `phi_models.py` 中以 SHA256 强制校验。这条记录说明"模型能跑"≠"模型真的在工作"，也是本阶段对推理链路做的前置验证。

## 2. 分类别结果（测试集 F1 / 金标数）

| 类别 | 金标 | A | B | C | D |
| --- | --- | --- | --- | --- | --- |
| DATE | 476 | 0.000 | 0.288 | 0.940 | 0.943 |
| ADDRESS | 484 | 0.000 | 0.131 | 0.691 | 0.710 |
| NAME | 477 | 0.000 | 0.657 | 0.789 | 0.790 |
| PATIENT_ID | 250 | 0.428 | 0.000 | 0.626 | **0.781** |
| PHONE | 175 | 0.573 | 0.414 | 0.890 | **0.994** |
| INSURANCE_ID | 54 | 0.000 | 0.000 | 0.737 | **0.812** |
| EMAIL | 15 | 0.000 | 1.000 | 0.966 | **1.000** |
| SSN | 11 | 0.000 | 0.300 | **1.000** | 0.629 |

可读出的结论：

- **规则补模型最有效的地方是"有结构标识符"**：PATIENT_ID 0.626→0.781、PHONE 0.890→0.994。这类字符串格式强、语义弱，正则天然合适。
- **SSN 是 D 唯一退化的类别**（1.000→0.629）：补充规则里的 `\d{3}-\d{2}-\d{4}` 会把部分金标 PATIENT_ID 误标为 SSN（13 个 SSN 误报）。这是"加规则"的真实代价，不是实现 bug。
- **Presidio 在 ADDRESS/PATIENT_ID/INSURANCE_ID 上接近失效**：它没有任何病历号或医保号识别器（本项目明确不自定义），且 LOCATION 与 ASQ-PHI 的 GEOGRAPHIC_LOCATION（含机构名）对齐很差。这是"方法不适配数据"的情况，按协议如实报告而非强行粉饰。

## 3. 分语言结果

| en | 456 | 0.058 / 0.110 | 0.474 / 0.443 | 0.866 / 0.789 | **0.936 / 0.819** |

两点必须说明：

1. **Presidio 在中文上召回 0.057 并非缺陷报告，而是设计事实**：它是英文 NLP 引擎，中文文本上几乎没有可用识别器。若只看总体分数会把方法 B 误判为"稍差"，分层后事实清楚——它是不适配。
2. 中文测试集只有 22 个 bootstrap 重采样簇（每条模板族一个），中文层的不确定性区间明显宽于英文（441 簇）。中文结论只能作为方向性参考。

## 4. 开发集选择（协议 v2.1，未接触测试集）

一次推理导出全部门槛候选后离线扫描，网格：C 的 t ∈ {0.05…0.90}、B 的 s ∈ {0.0…0.9}、D 的组合 ∈ {规则+GLiNER(t)} ∪ {规则+GLiNER(t)+Presidio(s)}。dev = 396 条。

选定结果（每方法独立，最大化 F1，并列取召回更高者）：

| 方法 | 选定 | dev Recall | dev Precision | dev F1 |
| --- | --- | --- | --- | --- |
| B | s = 0.10 | 0.362 | 0.406 | 0.383 |
| C | t = 0.20 | 0.801 | 0.791 | 0.796 |
| D | t = 0.20，规则+GLiNER（**不含 Presidio**） | 0.900 | 0.789 | 0.841 |

- 融合是否并入 Presidio 由 dev 决定：**并入后 F1 从 0.841 掉到 0.688、保护医学误删率从 6.9% 升到 29.1%**，因此被否决。
- 协议 v2 原本规定"先最大化召回，再在 1 个百分点内取 F1 最大"。在 dev 前沿上该规则选中了最低阈值 t=0.05，代价是掩码 22.8% 的保护医学字符、改动 100% 的硬负样本，等于放弃全部可用性。规则因此改为 F1 最大化。**该修订发生在读取任何测试集数据之前，但确实是在看到 dev 前沿之后作出的**，属于开发集驱动的设计修正；dev 全前沿与"召回优先"备选点都保留在 `reports/phase2_dev_sweep/sweep.json`，读者可自行判断。

## 6. 逐条错误分析（真实样例，均来自合成数据）

`reports/phase2_phi_v1/test_run/D/errors.json` 共 751 条，结构为：

| 类型 | 数量 |
| --- | --- |
| 误报 NAME | 230 |
| 误报 ADDRESS | 158 |
| 漏报 ADDRESS | 131 |
| 误报 PATIENT_ID | 98 |
| 误报 DATE | 58 |
| 漏报 PATIENT_ID | 27 |
| 漏报 NAME | 15 |
| 漏报 INSURANCE_ID | 13 |
| 误报 SSN | 13 |

**漏报（FN）模式**

1. **机构/所属结构地点**：`Dr. Smith's Office`、`our Chicago clinic`、`our Miami office`、`Brigham and Women's Hospital, Boston`。金标把"机构名+城市"整体标为地理标识符，模型通常只抓到片段或完全漏掉。
2. **缩写人名**：`James T.`、`John L.`。模型倾向带上称谓（`Mr. James T.`），与金标边界不一致 → 同时产生 1 个 FN 与 1 个 FP。

**误报（FP）模式**

1. **年龄短语被当成姓名**：`34-year-old female`、`55-year-old male` 被标为 NAME。这正是 ASQ-PHI 设计要暴露的过度脱敏——90 岁以下年龄在 Safe Harbor 下不是标识符。
2. **裸年份被当成日期**：`He was diagnosed back in 2021.` 中的 `2021` 被规则标为 DATE，而 ASQ-PHI 将其定义为非 PHI。
3. **临床缩写被当成编号**：`70yo M w/ CHF` 被标为 PATIENT_ID。

**可执行的下一步**（不在本阶段改，避免污染冻结结果）：把"机构名+城市"作为单一地点实体处理、把年龄与裸年份加入显式白名单、把称谓与人名边界统一到金标口径。

## 8. 本阶段真正解决了什么

1. **有了来源独立、可审计、零泄漏的评测集**（1,371 条，两个来源，8 类标签，审计 PASS）。旧 730/60 集退居历史诊断资料。
2. **把"PHI 召回 55.56%"的旧问题量化到底**：在独立数据上原规则召回只有 **8.03%**，说明旧指标既高估了模板内表现、也低估了泛化失败。
3. **给出了四路方法的真实对照**：融合 D 相对原规则召回 **+82.4 个百分点**（bootstrap 区间不含 0），相对单模型 C 召回 **+6.8 个百分点**。
4. **诚实记录了代价与失败**：Presidio 不适配中文与病历号/医保号；int8 量化权重表征坍缩；96.55% 硬负样本被改动；SSN 因补规则而退化。

## 9. 本阶段没有解决什么

- 没有任何人工医学标注；CLINICAL 保护层是程序代理，误删率只能横向比较。
- 预训练语料是否包含 ASQ-PHI 无法排除（ASQ-PHI 由 GPT-4o 生成）。
- 未做长病历文本、未做多语种扩展、未验证真实医院数据。
- 真实患者入口与正文出口**继续关闭**；本阶段未开启任何文本出口。
