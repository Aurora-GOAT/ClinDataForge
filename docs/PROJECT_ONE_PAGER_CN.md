# ClinDataForge 一页项目介绍

> 面向蚂蚁集团 2027 届「医疗大模型数据科学家—平台技术」岗位。个人求职项目，与蚂蚁集团无关联。
> 每个数字都能在 `reports/final/metrics_registry.json` 中查到产物路径与字段；本页不写无法回溯的指标。

## 项目一句话

为医疗大模型训练数据的长尾覆盖与隐私合规问题，构建一套**知识约束合成 → 九段结构化流水线 → PHI 脱敏 → 多层质量审计**的离线数据平台；本轮重点是**把已有成果验到可以经得起追问**：修上下文判定、提 PHI 吞吐、查数据血缘与切分关系、给共享常数表建独立核验路径。

## 五个可核验成果

**1. PHI 脱敏：第三方合成数据上的冻结对照（第二阶段）**
- 评测集 ASQ-PHI v1（MIT，第三方合成）+ 自建中文模板；近重复连通分量划分，独立审计零泄漏；冻结 test 632 条 / 1,942 实体，只评测一次。
- 规则 F1 0.1457 → Presidio 0.3446 → GLiNER 0.7920 → **规则∪GLiNER 0.8238（召回 0.9042）**；配对 bootstrap 区间不跨 0。
- 代价如实记录：漏 186 个实体、金标字符残留 5.36%、**96.55% 的无 PHI 硬负样本被改动**；真实患者文本入口与正文出口保持关闭。

**2. 上下文状态判定：从固定窗口改为作用域（第四阶段 P0）**
- 定位 783 例 `history→affirmed` 的四个作用域根因：段头冒号被当句界、接续只回溯一分句、中文实体名内含否定字（「前脑无裂畸形」的「无」）、固定 24/48 字符窗口。
- 按 NegEx/ConText 重写为 `ctxscope-1.1.0`：pseudo-negation 掩码、硬终止符、termination terms、最近触发词、段头延续。
- 开发集 **783 → 0**（仅诊断）。评测前另冻结 260 条同生成器留出语料：`history→affirmed` **221 → 0**，准确率 0.7021 → **0.9778**，宏 F1 0.6840 → **0.9567**；四类 F1 全部上升。词表消融把机制（0.8869）与扩词表（0.9778）分开。

**3. PHI 推理吞吐：profiler 驱动，2.79×（第四阶段 P1）**
- 真因不是"没批处理"：fp16 权重在无 AVX512-FP16 的 CPU 上退化为 Cast 模拟（24.5% 算子时间）。换同版本官方 fp32 + 4 线程：**2,778 → 995 ms/条（2.79×）**，p95 4,787 → 1,748 ms，吞吐 0.36 → 1.00 条/秒；端到端九段流水线 **79.1 → 42.0 分钟（1.89×）**；代价峰值内存 1,349.5 → 2,128.6 MB。
- 批处理是**负结果**（padding 浪费 > 调用节省），写进配置 `why_not_batching`。冻结集重算如实披露 **C 2 个 + D 1 个新增跨度、0 缺失**（D 一致率 0.9984），D 召回 0.9042 与漏检 186 未变，precision 0.7566→0.7562；**看到差异后不回改阈值**。

**4. 知识约束合成与数据质量审计（第三阶段 + 第四阶段 P2）**
- HPO 2026-09 快照（20,482 术语 / 12,867 疾病，SHA256 与许可核验），16 种人工核验罕见病，2,400 条中英双语病例；每个表型实体带 HP 编码、证据码（TAS/PCS/IEA）与文献来源。
- **新血缘清单（`lineage-1.0.0`）**：2,400/2,400 条记录、22,156/22,156 个表型实体都能回到该病的 HPO 注释集；记录级溯源与快照一致 2,400/2,400；跨度错误 0。
- **发现并公开历史不一致**：`disease_selection.json` 与实际生成只有 **3/16** 个疾病重合；它由早期算法选择器写出，当前选择器可精确复现，生成器后来改用 `CURATED_DISEASES`。历史文件不覆盖，新增 as-run 清单。
- 修复上下文后，SFT 候选状态标签污染 **823/21,353（3.85%）→ 0/21,640（0.00%）**；偏好对标签噪声 **22/2,332 → 0/2,355**；隔离 68→45（23 条原是上下文错判导致的假隔离）。

**5. 切分关系与检验常数的独立核验（第四阶段验收）**
- 切分：跨 train/dev/test 共享患者 0、精确重复 0、近重复 0；但 **test 记录 99.02% 的三元组已在 train 出现**，疾病名出现在 100% 的 train 正文（脱敏后 85.37%），金标还包含 `disease_suspected`——这是任务设计层面的捷径，不能据此声称泛化。
- 留出集：260 条只有 **186 种不同文本**，按 Jaccard≥0.8 合并后仅 **64 个簇**（最大 10 条）。按簇做 bootstrap：v2 准确率 95% CI **[0.9451, 1.0000]**，v1 **[0.6337, 0.7734]**；区间仍分离，但"260 条独立样本"的说法不成立。
- 检验常数：新增 `clinforge/lab_standards.py`，换算因子由分子式 + CIAAW 原子量推导（葡萄糖 180.156 g/mol、肌酐 113.120 g/mol），不 import 项目共享表；1,277/1,277 个检验值独立复算一致。注入错误实验：共享表路径 0 错，独立路径检出 **26 个换算错 + 10 个方向错**——证明循环验证确实存在，第二条路径确实能抓。

## 效力分级（简历口径必须带这一层）

| 层级 | 本项目做到什么 | 不能声称什么 |
| --- | --- | --- |
| 模板内自检 | 表型 F1 0.991、检验标准化 1,277/1,277、去重 40/40 对 | 不是独立评测，模板与金标同源 |
| 同生成器留出合成语料 | 260 条、评测前冻结、新种子/新句式、64 个近重复簇 | 不是独立临床验证，共享代码/疾病集/中文词表 |

| 模型训练 | **未进行**（SFT/LoRA/DPO 全未跑） | 不能声称任何训练收益 |

## 工程与边界

- 纯标准库核心 + 隔离 `.venv-phi`（onnxruntime / spaCy / Presidio 锁版本）；**170 项单元测试**通过；评测脚本 write-once、冻结 SHA256、拒绝覆盖历史产物；Git 本地提交，**未 push**。
- MedMCQA 在线评测 **BLOCKED**（无 API 授权）；门控 995 ms/条对在线服务仍太慢；常数级循环验证无法在本项目内彻底消除；分割要真正可泛化需按疾病留一划分，但统计功效不足。
- 未调用付费 API、未上传患者级数据、未租 GPU、未开放患者文本出口。
